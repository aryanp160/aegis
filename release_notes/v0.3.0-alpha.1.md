# Release Notes: v0.3.0-alpha.1

We are thrilled to announce the release of **Aegis v0.3.0-alpha.1**!

This release introduces the highly anticipated **Rule Engine**, transforming Aegis from a robust SQL parser into a true static analysis framework. The rule engine enables declarative authoring of security and schema best-practice checks using native AST traversal.

## Key Features

- **Rule Engine Core**: A fast, deterministic orchestrator (`aegis.engine.RuleEngine`) capable of analyzing thousands of AST nodes in under a second. Designed with immutability in mind to support future multiprocessing capabilities.
- **AST Visitor Pattern**: Leveraging `sqlglot` underneath, we've introduced the `ASTVisitor` base class. This allows rule authors to seamlessly target specific SQL syntax (e.g. `visit_create`, `visit_drop`) without writing complex recursive descent logic themselves.
- **Rule Registry**: A central `RuleRegistry` manages the discovery, lifecycle, and toggle states of all active analysis rules.
- **Deterministic Output**: Analysis results and violations are aggregated and strictly sorted by severity, path, and location to ensure CI environments get consistent output on every run.
- **Ten Core Rules**: The first batches of high-risk, operational safety, and styling rules are implemented out-of-the-box (AEG-101 to AEG-110).

## Architecture & API Cleanup

- We promoted `RuleEngine` to the root `aegis` package for a cleaner public API.
- Re-exported primary models (`ParsedMigration`, `RuleRegistry`, `RuleEngine`) in the top-level `__init__.py` module.

## Developer Experience & Quality

- **Comprehensive Documentation**: A new Python script automatically extracts and guarantees synchronization of rule definitions to Markdown (`docs/rules/AEG-*.md`). Added an in-depth [Architecture Guide](docs/rules/architecture.md) for custom rule authoring.
- **Benchmarking**: Shipped `scripts/benchmark_engine.py` verifying that Aegis evaluates tens of thousands of AST nodes in milliseconds.
- **Code Quality**: Hit 100% test pass rate with strict `mypy` typing and zero `ruff` formatting errors across the codebase.

## What's Next?
In **v0.4.0-beta.1**, we will focus entirely on user experience: introducing a beautiful command-line interface using `typer` and `rich` to surface these violations natively in the developer terminal!
