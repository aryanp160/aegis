# AEG-109: Missing SET lock_timeout

**Category:** Performance
**Severity:** WARNING
**Risk:** Without a lock_timeout, a migration waiting for a lock can block all subsequent transactions, causing an outage.

## Problem

Checks that migrations specify a short lock_timeout in PostgreSQL.

## Why it is dangerous

PostgreSQL transactions block queries queued behind them. Setting a lock_timeout limits this queue time, aborting the migration if it takes too long to acquire a lock.

## Unsafe SQL

```sql
ALTER TABLE users ADD COLUMN age INT;
```

## Safe SQL

```sql
SET lock_timeout = '2s'; ALTER TABLE users ADD COLUMN age INT;
```

## Remediation

Prepend a 'SET lock_timeout = ...' statement at the start of your migration script.
