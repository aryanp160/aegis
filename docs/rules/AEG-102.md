# AEG-102: Missing CONCURRENTLY on DROP INDEX

**Category:** Destructive
**Severity:** ERROR
**Risk:** High risk of blocking application queries because PostgreSQL locks the table during a standard DROP INDEX.

## Problem

Index dropping locks the table against concurrent reads/writes by default in PostgreSQL.

## Why it is dangerous

Dropping an index locks the table against reads and writes. On active tables, this lock can cause immediate query queuing. Using DROP INDEX CONCURRENTLY avoids locking concurrent traffic.

## Unsafe SQL

```sql
DROP INDEX idx_users_email;
```

## Safe SQL

```sql
DROP INDEX CONCURRENTLY idx_users_email;
```

## Remediation

Add the CONCURRENTLY keyword to your DROP INDEX statement.
