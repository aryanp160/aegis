# AEG-105: Foreign keys without NOT VALID

**Category:** Destructive
**Severity:** ERROR
**Risk:** Blocks table access by acquiring strong locks for historical verification checks.

## Problem

Adding foreign key constraints locks tables for a full validation scan unless NOT VALID is specified.

## Why it is dangerous

Adding a foreign key validates all pre-existing rows in the table. For large tables, this lock can cause downtime. Adding the constraint with NOT VALID skips immediate scan validation, allowing safe validation at a later point.

## Unsafe SQL

```sql
ALTER TABLE orders ADD CONSTRAINT fk_orders_user FOREIGN KEY (user_id) REFERENCES users (id);
```

## Safe SQL

```sql
ALTER TABLE orders ADD CONSTRAINT fk_orders_user FOREIGN KEY (user_id) REFERENCES users (id) NOT VALID;
```

## Remediation

Add the NOT VALID clause, then validate constraints using ALTER TABLE VALIDATE CONSTRAINT in a separate transaction.
