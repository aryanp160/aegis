# AEG-106: CONCURRENTLY inside transaction

**Category:** Destructive
**Severity:** ERROR
**Risk:** PostgreSQL throws an error and aborts the migration if a CONCURRENTLY index command runs within a transaction block.

## Problem

Running index operations CONCURRENTLY inside a transaction block will fail in PostgreSQL.

## Why it is dangerous

PostgreSQL requires CONCURRENTLY operations to run outside of transaction blocks (BEGIN/COMMIT) because they manage their own internal transactions.

## Unsafe SQL

```sql
BEGIN; CREATE INDEX CONCURRENTLY idx ON users (email); COMMIT;
```

## Safe SQL

```sql
CREATE INDEX CONCURRENTLY idx ON users (email);
```

## Remediation

Remove BEGIN/COMMIT transaction statements from the migration file, or run CONCURRENTLY operations separately.
